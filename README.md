# 视频资源下载器 · 0.12.0

Chrome / Edge 的 Manifest V3 插件。它识别播放器的资源请求，不录屏，不上传视频或浏览记录。不需要 CoApp 或其他本地辅助程序。

## 安装和使用

1. Chrome 打开 `chrome://extensions`。Edge 打开 `edge://extensions`。
2. 启用「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本项目的 `extension` 文件夹，不是整个项目文件夹。
5. 刷新要下载的网页，播放视频。
6. 点击工具栏中的「视频资源下载器」。直接文件可点击封面预览；HLS 可读取并选择清晰度，再点击「下载」。下载完成后，可在卡片中点击「打开」或「在文件夹中显示」。也可以在网页视频上点右键，选「用视频资源下载器下载这个视频」。
7. 可继续点击其他视频的下载按钮。需要同时查看多项任务时，点击「展开下载面板」在浏览器标签页查看。每项任务分别取消、重试。

插件会保存到浏览器下载目录的 `VideoDownloads` 子文件夹。同名文件不会覆盖已有文件。浏览器开启「下载前询问保存位置」时，由浏览器显示保存窗口。

插件需要读取 HTTP / HTTPS 网页请求，才能发现跨域 CDN 上的视频。浏览器会显示网站访问权限提示。只在你信任的网站启用；收窄网站权限后，跨域资源可能无法识别或下载。

## 本次支持范围

| 资源 | 行为 |
| --- | --- |
| 直接视频文件，例如 MP4、WebM | 使用浏览器下载管理器保存原文件，不转码 |
| HLS 主清单 | 默认最高带宽，可读取并选择清晰度；解析相对地址及 HTTP 重定向后的地址 |
| 连续、非加密、音画已合在一起的 MPEG-TS HLS 点播 | 按顺序下载全部片段，转封装为 `.mp4`，不重新编码。编码不能原样放入 MP4（例如 MPEG-2 视频）或转换失败时，保存完整的原始 `.ts` 并说明原因 |
| 非加密 H.264 / AAC fMP4 HLS 点播 | 下载全部音画片段，支持独立音轨，封装为普通 `.mp4`，不重新编码 |
| DASH 清单 | 列出资源，明确标记暂不支持下载 |
| 加密 HLS、DRM、直播、MPEG-TS 独立音轨、字节范围片段、不连续片段 | 不支持；HLS 检查失败会停止，不保存残缺文件 |

TS 转 MP4 只复制原有音画数据包，不重新编码，画质不变；不是把 TS 改名为 MP4。只复制 H.264 / HEVC 视频和 AAC / MP3 / AC-3 / E-AC-3 音频，其他编码保留 TS，避免浏览器偷偷重新编码。转换后逐条轨道核对数据包数量，并核对时长与清单一致；任何一项不一致都保留 TS。当前支持读取 HLS 主清单并手动选择其中的清晰度。支持上述 fMP4 封装和音轨合并；不支持转码、MKV 封装或断点续传。未知直接文件类型使用 `.bin` 后缀，不假装成 MP4。

HLS 限制：最多同时处理 3 个任务，更多任务排队；每任务最多 10000 个片段、单次请求 60 秒超时、单个清单不超过 2 MiB、最多 5 层清单。TS 逐块写入浏览器临时磁盘，不再受 256 MiB 总大小限制；仍受浏览器存储配额和可用磁盘空间限制。转换时 TS 和 MP4 两个临时文件同时存在；转换成功后先删除 TS，再保存 MP4，此时临时 MP4 和最终文件同时存在。请预留至少两份视频的空间。fMP4 音画封装仍使用内存，输入数据总计不超过 256 MiB，这不是进程内存上限。直接文件由浏览器写盘，不受这个 HLS 大小限制。

网页导航会清空旧资源。关闭下载面板不会终止任务；重新打开仍可查看状态或取消。关闭浏览器、禁用或重载插件会中止 HLS，不提供恢复。

## 登录、隐私和已知限制

- 只下载你拥有保存权利的内容。插件不破解 DRM，不绕过登录或付费权限。当前版本连普通 AES-128 HLS 加密也不处理。
- 不读取、复制或保存 Cookie；浏览器按自身规则决定是否随下载 / HLS 请求发送已有 Cookie。
- 不复制播放器的 Cookie、Authorization 或其他私有请求头。HLS 请求使用实际视频页面的域名来源（Referer，只发送 origin + /，不包含页面路径或参数）。只对本插件发起的单个 HTTP(S) 媒体请求临时设置，收到响应头后清理；不改普通网页请求、Origin 或浏览器鉴权信息。不向 HTTP 地址泄露 HTTPS 来源。依赖其他私有请求信息的网站仍可能失败。
- TS 下载数据及转换中的 MP4 临时存放在本插件专用的浏览器私有磁盘目录。完成、失败或取消时删除；浏览器退出、插件重载或意外中止后，下一次 HLS 处理页面启动时清理遗留数据。不提供断点恢复。
- 资源 URL、网页视频标题、封面地址、视频元数据、所有活动任务和最近 100 项结束任务只保存在 `chrome.storage.session`，不写入持久存储。URL 可能包含临时访问令牌；不要把它们发给其他人。
- 无分析服务、遥测、远程代码或视频上传。网络访问只有目标视频 / 清单 / 片段、网页视频的封面，以及网页原有请求。
- blob URL 本身不是可下载的视频文件。插件等待播放器发起实际资源请求。不能发现所有播放器的资源；已过滤 X 的已知初始化 / 音轨资源；直接 MP4 下载前检查是否含实际视频数据。此检查不能保证原网站提供了整部影片。
- 最多保留每个标签页最近 100 个资源。广告视频也可能出现在列表中；下载前检查文件名和来源域名。
- Chrome 内部页面和扩展页面不支持资源识别。Firefox 不在本次支持范围内。

## 行为约定和验收

目标：用户播放自己有权保存的视频，打开插件并点击下载，得到原视频或完整的 MP4 点播文件。不能用录屏、改后缀的假 MP4 或只含部分片段的文件代替。

| 假如 / 当 | 应观察到的结果 |
| --- | --- |
| 网页已请求 MP4，点击下载 | 文件与源文件逐字节一致，含完整音画，能解码 |
| 网页已请求 HLS 主清单，点击下载 | 下载所有片段，输出 `.mp4`，解码后的每一帧画面和声音与原 TS 一致 |
| HLS 编码不能原样放入 MP4 | 保存完整原始 `.ts`，完成状态说明原因 |
| 下载完成，点击「打开」或「在文件夹中显示」 | 用系统默认程序打开文件，或在访达 / 资源管理器中选中文件；文件已被移走时显示原因 |
| 关闭并重开面板 | 保留当前下载状态 |
| HLS 加密、直播、片段 HTTP 错误、独立音轨 | 显示原因，不保存残缺文件；加密清单不请求密钥 |
| 取消下载后再次下载 | 任务停止，可以重新下载；不遗留忙碌状态 |
| 页面请求 DASH | 可识别但下载按钮禁用 |
| 切换到另一标签页或原页面导航 | 不显示其他页面或旧页面的资源 |

测试先于实现编写。最初因缺少插件而失败，记录在 `artifacts/initial-red.log`。验收使用隔离的 Chromium 配置、真实扩展 API 和本地生成的三秒音画视频，不访问用户的浏览器会话。HLS 识别测试通过网页请求清单触发；输出另用 FFprobe 和 FFmpeg 检查、解码，不代表第三方 HLS 播放器兼容性已验收。

## 结构与官方参考

- `extension/background.js`：网络识别、每标签页资源列表、下载状态和下载管理器。
- `extension/content.js`：采集网页视频地址、标题、封面和元数据；定位原视频。
- `extension/resources.js`：按直接地址、清单关系和 X 媒体 ID 关联、归组资源。
- `extension/hls.js`、`offscreen.js`：清单检查、片段下载、TS 流式写盘、TS 转 MP4 和临时文件清理。
- `src/mp4.js`：Mediabunny 封装入口（fMP4 合并、TS 转 MP4），由 `npm run build` 打包到 `extension/vendor/mp4.js`。
- `extension/popup.*`：视频卡片、原文件预览、真实下载反馈、错误及取消。
- `extension/version-picker.js`：真实版本列表、选中状态与键盘操作；使用浏览器原生 popover。
- `tests/e2e.mjs`：真实扩展端到端验收。

依据：[Chrome webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest)、[downloads](https://developer.chrome.com/docs/extensions/reference/api/downloads)、[offscreen](https://developer.chrome.com/docs/extensions/reference/api/offscreen)、[HLS RFC 8216](https://datatracker.ietf.org/doc/html/rfc8216)、[Playwright 扩展测试](https://playwright.dev/docs/chrome-extensions)。

## 页面归属修复 · 0.5.0

### 行为约定

- X 站内切换帖子（不刷新整页）时，清空上一页面的资源和播放器关联。不能用旧视频冒充当前帖的视频。
- 旧页面已经发出的请求迟到时，不把结果重新加入新页面。能读到完整 Referer 时核对来源页面；跨站只提供域名时不猜路径。X 帖子另按当前播放器的明确媒体 ID 过滤。
- X 帖子仅关联包含当前帖子链接的播放器，不把尚未移除的旧帖子或回复视频混进当前帖子。
- X 未匹配资源显示“等待匹配”，不允许启动下载。点击下载时也检查资源所属页面，拒绝旧页面条目。
- 切页不取消已经开始的下载；任务明确标注“上一页面的下载”，不挂到新视频卡片。
- 页面标题跟随当前网页，不保留上一页标题。

### 验收与边界

## 双击即可播放 · 0.10.0

目标：HLS 下载完成后，用户双击文件就能用系统播放器打开；在插件里也能直接打开文件或找到文件。

- 原因：macOS 能解码这类 TS，但 `.ts` 也是 TypeScript 代码文件的扩展名。装了代码编辑器的电脑上，双击 `.ts` 往往会打开编辑器。上传网站或聊天软件也常不认识 `.ts`。
- TS HLS 下载完所有片段后，在浏览器私有磁盘中转封装为 MP4。读写都走磁盘，不受 256 MiB 内存限制。只复制音画数据包，不重新编码：编码先过白名单，Mediabunny 再以「只复制」模式运行，复制不了的轨道会被拒绝而不是重新编码。转换后逐条轨道比对 TS 与 MP4 的数据包数量，再比对时长与清单。编码不在白名单、转换出错、数据包缺失或时长不一致时，保存完整原始 TS，完成状态写明原因和文件名。
- 清晰度菜单中，原来显示为 TS 的版本现在显示为 MP4，表示实际输出格式。
- 完成状态显示浏览器实际保存的文件名（重名时带编号），并提供「打开」和「在文件夹中显示」。新增 `downloads.open` 权限，只在用户点击「打开」时使用。
- 行为验收：TS 输出用 FFmpeg 逐帧解码，画面和声音的每帧哈希都与原 TS 一致；超过 256 MiB 的 TS 输入同样逐帧一致，临时目录清空；MPEG-2 视频的 TS 保存为逐字节一致的原始 TS 并显示原因和文件名；清单时长与实际内容不符时同样保留原始 TS；打开和显示按钮把正确的下载编号交给浏览器，文件被移走时显示错误。测试中用记录函数替代真实打开，避免在测试机上启动播放器或访达。
- 证据：`artifacts/open-mp4-0.10.0/report.json`、`open-actions.png`、`open-actions-dark.png`、`large-ts-complete.png`，以及同目录 `downloads/VideoDownloads/` 的实际文件。
